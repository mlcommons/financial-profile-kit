# Changelog

All notable changes to the Agent Reliability Profile Kit. Finding IDs (A-, B-, C-) refer to the three independent reviews of release candidate 1 (October 2026): A = specification against the preprint, B = code and tests, C = adopter experience.

## Unreleased: repository packaging

No change to the specification, schemas, vectors or tool behaviour.

- Set up as a GitHub repository, `mlcommons/financial-profile-kit` (private until release).
- `COMPATIBILITY.md`: the three governed parts (taxonomy, specification, tools), their versions, the supported combinations and the known wording differences with the pinned taxonomy release.
- `spec/taxonomy.lock.json` pins taxonomy release 0.1.0 and records which vocabulary files and fields the taxonomy owns; `tools/check_taxonomy_vocab.py` checks `spec/vocab/` against that release (no identifier or assignment mismatch; seven wording differences listed in COMPATIBILITY.md).
- `governance/`: roles, review process (specification changes: Working Group; tool changes: maintainers; vocabulary changes: taxonomy repository) and a shared release checklist built from the rc2 review gates.
- `.github/`: CI for the full test suite and the taxonomy check; a release workflow that drafts a GitHub release with the Kit zip, a Builder skill zip and SHA-256 checksums; issue templates (specification change, bug report, implementation report); MLCommons CLA bot (skipped while private).
- `CITATION.cff`, `.gitignore`. `tools/make_release_zip.py` treats `.gitignore` and `.gitattributes` as never shipped. `REVIEW-rc2.md` (internal) is not part of the repository.

## arp/1.0-rc2 (2026-10-22)

Release candidate 2 of arp/1.0, prepared by the MLCommons Financial Services Working Group for pilot use and comment. Not a final MLCommons standard, certification scheme or endorsement. Changes from arp/1.0-rc1 (7 October 2026).

#### Canonical form and signatures
- [A-04, B-02] Canonical form is RFC 8785 (JCS): UTF-16 key order, ECMAScript number and string serialisation. Implemented identically in Python and the Viewer; verified against Node's JSON.stringify on 8,613 numbers with 0 mismatches. Numbers of magnitude 2^53 or more, NaN/Infinity and unpaired surrogates are rejected (ARP-001) (SPEC §7, arp_conform.py, viewer.src.html).
- [A-04, B-02] Every parsable vector records its `canonical_hash` in the manifest; run_suite and test_viewer check it; `run_suite.py --impl-hash` tests another implementation's hash (conformance/build_vectors.py, run_suite.py, test_viewer.mjs).
- [B-03] Signatures are Ed25519 over a signature statement {context, alg, role, name, organisation, public_key, signed_hash}, so role, name, organisation and key are covered; duplicate signatures are rejected; an assessor may not use the owner's key; §7 wording corrected (SPEC §7, ARP-014, ARP-091, arp_conform.py, viewer).
- [A-19] New `evidence_manifest` {content_hash, signer, public_key, value}: the signed source manifest; required at Level 2+ and verified whenever present (ARP-019); `arp_conform.py sign-manifest` creates it (schema, SPEC, checker, viewer).
- [B-15] Published DEMO-ONLY public keys are on a denylist: warning ARP-092 on signatures and evidence manifests (all stages), and a "DEMO KEY: proves nothing" label in the Viewer. (Deviation: warning, not an error on issued Profiles, so that the shipped examples stay conformant. See the report.)
- [A-29] ARP-091 wording: a checker that cannot check signatures reports "indeterminate" and never "conformant"; "verify" is no longer used for signatures (SPEC §5).

#### Strict input and parity (Python ↔ Viewer)
- [B-12] `loads_strict`: UTF-8 (BOM ignored), no duplicate member names, no NaN/Infinity, numbers that overflow rejected, top level must be an object, deep nesting caught; all reported as ARP-001. CLI exit codes 0 conformant / 1 not conformant or refused / 2 usage / 3 input or tool error; `--json` always prints JSON (arp_conform.py).
- [B-13] Duplicate member names rejected in Python (object_pairs_hook) and in the Viewer (`parseStrict`), with a vector (i39) (arp_conform.py, viewer.src.html).
- [B-06] Parity fixes: `hasOwn` instead of `in` (constructor/__proto__/toString), `benchmark` "present" means not null in both, placeholder matching uses ASCII boundaries in both, patterns match the whole string in Python (ECMA `$`), strict base64 via schema patterns and length checks, strict dates in both. A 100-case mutation comparison shows 0 differences (arp_conform.py, viewer.src.html).
- [B-07] `date` and `date-time` are validated by the checker's own strict parsers (zero-padded, real calendar dates, RFC 3339 with offset), independent of the installed jsonschema version; date rules compare dates, not strings (arp_conform.py, viewer).
- [B-12] `sign` and `sign-manifest` require `--out` or `--in-place` (no silent overwrite); refusal messages name the rule and path (B-17).
- [B-17] `sign --role issuer` on a draft is refused with "sign as owner first"; signing the same role and name twice is refused (arp_conform.py).
- New `pubkey` command prints a key's public key (C-14) (arp_conform.py).

#### Rules added or changed (SPEC §5; checker and Viewer)
- [A-01] ARP-060 now also requires the finding to be of kind `floor_failure` and checks floor↔finding links both ways; new ARP-061 (an issued Profile cannot contain a failed floor); new ARP-062 (Level 2+ needs floors; floors on tested axes, and Profile-wide floors on a Level 2+ headline, cannot be untested). Floors gain optional `axis`.
- [A-02] Disclosures: `not_comparable` is always required (reworded: "Production results in this Profile are specific to this deployment's environment…"); new `benchmark_not_production`, required when the flag is set (ARP-015, SPEC §6).
- [A-03, A-09] `assurance.assessor_role` replaced by per-axis `assurance.assessors.{autonomy,odd,actions,controls}` {role, organisation, report}. ARP-014: Level 3 ⇔ independent assessor; a Level 3 assessor is named, cites an `assessor_report` evidence item, and signs with role `assessor` and its organisation; signatures gain `organisation`.
- [A-05] ARP-080: issued Profiles need `valid_until` and `evidence_as_of`; `valid_from` may not precede the issue date; no date before 2000-01-01 (catches the 1970 sentinel, C-11); `check --as-of` warns on expired / not-yet-valid (B-14).
- [A-06] Invalidation items are objects {trigger, ref?, description}; new vocab/invalidation-triggers.json; optional `invalidation.monitoring`; ARP-082 (warning) for missing default triggers.
- [A-07] Platform Baseline Profiles declared out of scope for rc2 ("a platform MUST NOT issue one with this schema"); new ARP-083: an anchored Profile must list `platform_baseline_void` (SPEC §2, §9).
- [A-08, A-27] ARP-090: an issued Profile names its issuer; the owner signs under `issuance.owner.name`; an issuer other than the owner signs too.
- [A-10] ARP-020: a set flag needs a `benchmark` with an independent, accredited assessor and at least one result; `benchmark` has a schema; warning when the flag is set on an all-Level-1 Profile (B-14).
- [A-11] ARP-011: a `measured` field must be tested by a result; warning when a judged field is not `measured`.
- [A-12, A-13] ARP-041: substantiated T2 needs `resource_displayed: true`, `sample_size` > 0 and no simulated/suspected-simulated evidence conflict on autonomy; `substantiated` is T2-only; warning when a tested T2 lacks `habituation_catch_rate`. approval_quality gains `consequence_displayed` and `sampled_review_quality`.
- [A-17] New ARP-053: `use_case_id` must be catalogued (ODD.1–52) or `ODD.x_…`, and match the business line; warning when an issued Profile has none. Pattern no longer admits ODD.0.

- [A-20] ARP-040: tier U must be `asserted`, carry no approval_quality, and say "no reliability claim"; an issued U needs a risk acceptance or a remediation/suspension `response` on its finding (open findings gain `response`). v04 statement fixed.

- [A-25] Implemented-but-unstated checks are now stated (draft-signature warning in ARP-090; the old ARP-091W is ARP-091 at warning severity); the old issuer-independence cross-check is replaced by per-axis assessors.

- [A-30] ARP-031 is an error on issued Profiles (warning on drafts); out of scope vs A− explained.
